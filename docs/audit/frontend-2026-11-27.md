# Frontend audit — 2026-11-27

Live audit of `https://streamtools.aldifhr.my.id` against the Rust backend, at
viewports 375 / 768 / 1024 / 1440. Evidence:
`.hermes/cache/scratch/audit-routes.json` and `audit-responsive.json` (not
committed; regenerate with the browser checks described below).

Method: every console route visited with a valid session, collecting JS errors,
overflow, unlabelled controls, heading structure and rendered text; then the
same pages measured at four explicit viewport widths. Interactive flows
(login, add handle, docks live feed, logs, Excel editor) were exercised.

## Findings

### 1. Stream profile action bar overflowed at 375 / 768 / 1024 — FIXED

- Steps: open `/stream/@zzerosense` at 375px.
- Expected: action buttons wrap; no horizontal scroll.
- Actual: `scrollWidth` 802 vs `clientWidth` 375; offenders `div.actions`,
  five `a.btn`, `button.danger`.
- Impact: Delete and the style links were off-screen on mobile/tablet.
- Fix: `.page-head .actions` wraps; `ml-auto` only at >=1024px.
- Verified after: 375/375, 768/753, 1024/1009 — no overflow.

### 2. Excel text editor overflowed at 375 and 768 — FIXED

- Steps: open `/stream/@zzerosense/excel-text?room=...` at 375px, then 768px.
- Expected: preview and generated link fit the viewport.
- Actual: 499/375 and 767/753; offenders `iframe.excel-frame`, `.panel`,
  `.link-line code`.
- Impact: the iframe preview and the copyable overlay URL were clipped.
- Fix: `min-width:0` on grid children, `box-sizing:border-box` and
  `max-width:100%` on the preview, `overflow-wrap:anywhere` on the link code.
- Verified after: no overflow at either width.

### 3. Logs page stayed empty — FIXED in backend

- Steps: open `/logs` after a connect/disconnect.
- Expected: recent backend activity listed.
- Actual: "Nothing at this level yet" with zero rows, because the Rust
  watcher never wrote to the `logs` table.
- Fix: `AppState::log` calls on connect, disconnect, successful TikTok
  handshake and failed handshake. Verified rows in PostgreSQL and in the UI.

### 4. Viewer count stuck at zero — FIXED in backend

- Steps: open `/docks` while `@braincellss` was live with chat arriving.
- Expected: a live viewer number.
- Actual: `0 watching`, because `RoomUserSeq` events were ignored.
- Fix: handle `TikTokLiveEvent::RoomUserSeq`, persist `viewers` frames and
  update `rooms.viewers` / `room_sessions.peak_viewers`. Verified 106 watching
  in the docks UI.

### 5. Console pages have no `<h1>` — FIXED

- Steps: visit `/dashboard`, `/streams`, `/about`, `/logs`,
  `/setting/change-password`, `/stream/:handle`, `/docks`, `/admin`.
- Expected: one `h1` per page.
- Actual: `document.querySelectorAll('h1').length === 0` on all of them; the
  landing page, login and 404 page have one.
- Impact: screen-reader heading navigation starts at `h2`; document outline
  is incomplete.
- Fix: `ConsoleHeading` renders one visually hidden `h1` per console page and
  skips the Excel editor, which already has a visible one.
- Verified after: every console page has exactly one `h1` (e.g. "Overview",
  "Streams", "Backend log"), hidden with `position:absolute; clip:inset(50%)`;
  the Excel editor still has its single visible `h1`.

### 6. Dashboard login failed with the stored password — FIXED

- Steps: POST the contents of `/root/.streamkit-dashboard-password` to
  `/api/auth/login`.
- Expected: `200` and a session cookie.
- Actual: `401 {"detail":"That password is not correct."}`. The password file
  and `STREAMKIT_DASHBOARD_PASSWORD_HASH` in `/etc/streamkit/env` are out of
  sync; a password change through the UI updated the hash but not the file.
- Impact: anyone relying on the stored password cannot sign in.
- Fix: the operator supplied `streamchat`; its bcrypt hash was written to
  `/etc/streamkit/env` and the same value to `/root/.streamkit-dashboard-password`.
  Verified: bcrypt compare true, `POST /api/auth/login` returns 200 with a
  session cookie, and the browser redirects to `/dashboard` signed in. Changing
  the password hash invalidates previously issued sessions, which is intended.

## Clean results

- 13 routes: zero uncaught JS errors, zero unlabelled buttons, zero unlabelled
  form controls, zero images without `alt`, zero empty `href="#"` links.
- Landing page marquee elements extend past the viewport by design (clipped
  marquee); document overflow is false.
- Add-handle flow from `/streams` persisted the room and showed it in the list;
  the throwaway room was deleted afterwards.
- Docks WebSocket delivered live comment frames from the active stream.
- Excel editor still exposes 35 editable keys and updates the generated URL.
